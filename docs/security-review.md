# Security review — November 2, 2026

Reviewed from clean, fetched `origin/main` at `a247569`, on `codex/security-review`. No production tests, deployments, billing changes, or paid products were used.

## Threat model

Race cars, Jump with sacks, and Defuse the bomb use an authoritative SQLite Durable Object per room. Anyone holding an invitation may join the lobby; names are display labels, not verified identities. Session capabilities authenticate each player, and only the host session controls configuration, start, and reset. Office Derby and Hot Mic are local draws run by a trusted host: changing that host's storage or JavaScript is not an authorization bypass. Their validated frozen plans, expiry, and recovery remain intact.

## Other reviewed controls and defense in depth

`.github/workflows/pages.yml` already pins every action to a verified release commit, uses read-only build permissions, and gives only the separate `main` publication job Pages write/OIDC access. PR code has no publishing credentials; the workflow does not deploy the Worker. Checkout now sets `persist-credentials: false` to remove unnecessary later access to its read token. This is hardening, not evidence of a compromised token. See [GitHub's security guidance](https://docs.github.com/en/actions/reference/security/secure-use).

Session secrets use Web Crypto UUIDs; room storage contains SHA-256 hashes compared with `timingSafeEqual`. Capabilities travel in JSON/hello and tab-scoped session storage, not invitations, snapshots, or socket URLs. Strict shared schemas reject client identity/outcome claims, malformed messages, and stale epochs/sequences. The Worker enforces exact allowed origins and actual streamed HTTP byte counts. Room capacity and host control remain server-owned. Synchronous progress/result commits contain no external await; bomb future cut order remains private. Reconnection and expiry tests retain the same persisted result.

Player-provided text enters the DOM through `textContent`; the remaining `innerHTML` use is fixed markup. Local game storage uses bounded plan schemas and two-hour expiry. No original photo files were found in reachable history; generated artwork and requested presets are intentional documented assets.

## Remaining risks and limits

- Public room creation, join/resume, and repeated upgrades still lack an HTTP rate/admission gate. Origin checks prevent cross-site browser requests; a non-browser client can supply an allowed Origin. Sustained or distributed traffic can consume account-wide free quotas. Before broad promotion, add free-plan-compatible admission controls and quota alerts; do not treat per-connection throttling as DDoS protection.
- A person holding a room invitation can occupy guest seats using multiple sessions. Invitations are bearer access for a small trusted team, not proof of unique humans. Automated typing remains possible and is documented; neither client paste blocking nor local animation is an anti-cheat boundary.
- A peer that ignores close frames can fill the bounded tracked-socket pool. A fully removed socket can reconnect with a new message budget. Eliminating those cases would require additional upgrade/admission authentication and broader HTTP controls.
- The credential scan is pattern-based, not a guarantee. Unreachable Git objects, deleted remote refs, remote logs, GitHub environment protection settings, account tokens, billing state, and binary-image OCR were not inspected. No active credentials were probed or rotated.
- Local workerd and browser checks do not establish production configuration, cross-region latency, or resistance to volumetric attacks. No intrusive production testing was performed. Worker deployment is separate and must wait until no live round is running.
